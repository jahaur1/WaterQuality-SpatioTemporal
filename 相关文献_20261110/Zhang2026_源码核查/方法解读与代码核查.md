# Zhang等（2026）D-TGCN：方法解读与公开代码核查

核查日期：2026-11-10。论文：*Incorporating Flow Direction as a Physical Prior in Graph Networks: A Directed Temporal Graph Convolutional Network for Enhanced Water Quality Forecasting in Lake Basins*，*Transactions in GIS*, 30(4), e70309。

[出版社论文页](https://doi.org/10.1111/tgis.70309)；[论文直接链接的作者仓库](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality)。当前出版社full-text链接仍返回摘要页，因此下文详细实现结论主要针对公开master分支，不等同于已完整审读论文正文或复现其正式实验。本轮没有运行原论文训练，只做源码检查和最小计算核验。

## 1. 核心做法

先提供监测站上下游关系，生成有向图，再在GRU的状态更新中用图卷积聚合相连站点信息，最后输出各站未来水质。空间关系由已提供的关系清单决定，时间关系由递归模型学习。

作者仓库的典型预测链：

```text
过去7天所有站的某一种水质指标
              ↓
固定上下游有向邻接矩阵
              ↓
逐日图卷积＋GRU更新
              ↓
各站64维隐藏状态
              ↓
共享线性预测头
              ↓
下一天所有站的该项水质指标
```

## 2. 图从哪里来：已整理的上下游关系清单

公开文件`Adjacency matrix related/station flow direction relationship.txt`列出站点编号、中文断面名及流向，共61条关系，涉及60个命名站点。例如作者清单中的两条支流汇流关系：

```text
桃江江口 ──→ 新庙前
上犹江江口 ─→ 新庙前
```

`adjacency matrix generation.py`读取站点顺序Excel和上述清单：若i为上游、j为下游，赋值A[i,j]=1；无向对照再额外令A[j,i]=1。原始边权只有0和1，不使用直线距离高斯核、不从水质Pearson相关性学习边，也没有在这个脚本里自动搜索地图或推断水文方向。

实读已发布矩阵：鄱阳湖有向矩阵60×60、61个非零值；无向矩阵60×60、122个非零值。说明有向与无向对照的差别首先是边的方向。关系清单的外部水文证据如何整理，当前开放脚本本身未完整交代，不能仅凭清单断言每条边已经独立核实。

[建图脚本](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/Adjacency%20matrix%20related/adjacency%20matrix%20generation.py)；[流向清单](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/Adjacency%20matrix%20related/station%20flow%20direction%20relationship.txt)。

## 3. 图方向怎样进入计算

`utils/graph_conv.py`先加自身连接M=A+I，取原始M的行和构造D，返回：

S = D^(-1/2) M^T D^(-1/2)

转置把存储时的“行上游、列下游”改成乘法需要的“行接收、列发送”。函数名字含laplacian，但返回的是归一化的消息传播矩阵，不是通常定义的I减归一化邻接。

已用两节点例子核验：仅A[上游,下游]=1，上游非零输入能够传给下游，反方向矩阵项为0；方向没有被强制对称化。具体归一化用原行度，保留了作者实现，不替其改成其他有向归一化方案。

[归一化代码](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/utils/graph_conv.py)。

## 4. 模型结构

`models/tgcn.py`在每个时间步拼接当前节点输入x_t和上一时刻隐藏状态h_(t-1)，先做S[x_t,h_(t-1)]W+b。两次图卷积分别用于GRU的门控及候选隐藏状态，再递归更新。完整序列读完后得到每站64维隐藏表示，`tasks/supervised.py`使用共享线性头映射到未来pre_len步。

其设计意图是：更新节点状态时同时参考水文相连节点，空间关系在时间递归内部参与，而不只在最终预测后增加一个图校正头。公开代码的门控拆分存在实现问题，详见第7节；上述是结构意图，不能忽略该问题后直接认定其实现严格遵守全部图约束。

默认接口输入[B,7,N]，输出[B,N,1]。核查到的TN入口只加载`daily_tn_Poyang_timeseries.csv`，因此是单指标、多站点、下一步预测；仓库另有DO、水温、CODMn、NH3-N、TP等独立入口。仅列出六项预测实验，不代表这些变量在一个模型里共同输入和共同输出。

在所查默认路径中没有发现未来5项易测协变量接口、LoRA、预训练骨干、流量驱动动态边更新或逐边传播时滞学习。GRU能够学习时间依赖，但不提供显式“这条边传播几小时”的变量。

[TGCN模型](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/models/tgcn.py)；[预测任务](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/tasks/supervised.py)；[TN入口](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/tgcn-torch_tn.ipynb)。

## 5. 数据与训练

README说明使用2019—2023年日尺度数据，包括鄱阳湖流域和赣江子流域。实际读取赣江TN CSV得到1,826行、27列，列为站点编号；鄱阳湖矩阵为60站，TN notebook保存的张量形状也显示60站。赣江是从鄱阳湖站点集中筛出的子流域，不能直接当作完全不重合的独立流域测试。

公开默认设置：历史7步、未来1步、隐藏64、batch64、学习率0.001、顺序切分前80%与后20%，notebook配置上限1000个epoch。原数据表由README解释为日尺度，所以7步对应7天、1步对应下一天；CSV本身无独立时间戳列时，不应从行号推断更多具体采样细节。

损失函数默认是平方误差之和的一半加L2正则；训练器使用Adam。数据模块将后20%作为val_dataset，每轮评估；任务的test_step为空，TN notebook回调按train_loss保存模型，再调用validate。当前公开入口没有清楚分开的训练、调参验证、最终盲测三段。

与我们当前750站、30天、小时级精确24小时配对、历史9项及未来5项易测实测的任务不同；也与我们24次更新预算不同。不能用论文或notebook的整体R²数值直接对比我们的逐站四指标平均R²。

[数据模块](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/utils/data/spatiotemporal_csv_data.py)；[滑窗和切分](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/utils/data/functions.py)。

## 6. 与我们现有方法的关系

| 项目 | 作者公开默认路径 | 我们当前主要设置 |
|---|---|---|
| 图来源 | 已提供的上下游清单，固定二值有向图 | 相关、自适应、粗定位距离、候选河网及统计时滞 |
| 站点规模 | 鄱阳湖60、赣江子集27 | 750 |
| 数据跨度 | README说明5年日序列 | 当前实验30天 |
| 输入 | TN示例为所有站的历史TN | 本站历史9项，允许未来5项易测实测 |
| 输出 | TN示例为所有站下一天TN | 24小时后4项化学值 |
| 时间骨干 | 从头训练GRU，内部融合图卷积 | Chronos-2末两层LoRA与空间残差模块 |
| 显式边时滞 | 未在核查路径发现 | 已做0/4/8/12/24小时关系选择试验 |

最值得借鉴的是经过整理的水文连接先验、同一数据上的有向/无向/无邻站消融，以及空间信息在时间递归内部参与的方式。不能期待仅换用TGCN就补足站点定位和河段归属信息。

## 7. 公开代码需要修正的三个问题

### 7.1 R²分母用了预测均值

`utils/metrics.py`使用sum((y-mean(pred))²)，标准R²应使用sum((y-mean(y))²)。该代码还整体汇总时间与站点，而我们的主指标是逐站计算后平均，两者统计口径不同。

最小例：真实[0,1,2]、预测[1,2,3]。作者函数返回约0.4，标准R²为−0.5。已实际执行验证。公开代码的这个R²不能直接用于评价或与我们结果横比；不能仅凭此认定正式论文所有表格都来自这个函数，仍需核对正文及生成记录。

[指标源码](https://github.com/GeoScene-Lab/FlowAware-TGCN-WaterQuality/blob/master/utils/metrics.py)。

### 7.2 在时间切分前使用全数据最大值

`generate_dataset`先对全部输入求max_val并归一化，再做80/20切分；数据模块也从全部输入取feat_max_val。按照严格时间前推评估，应先切分，在训练段拟合尺度，再应用后续段。它不是直接读取未来标签训练权重，但引入了后续数据的尺度信息，复现时应修正。

### 7.3 GRU门控展平后拆分，破坏节点隔离

图卷积1返回[B,N*2H]，代码直接沿展平维度chunk成两半，未先恢复[B,N,2H]再沿最后一维拆分r和u。其节点和门的排列可能交错，导致其他节点的门控进入本站状态更新。

实际最小检查：2节点、单位邻接、隐藏维度2、固定随机种子1。保持节点0历史不变，给节点1全部输入加10，原模型节点0的最终隐藏状态最大变化约0.134156。把门拆分暂时改为逐节点执行后，变化为0。改动只在check.py运行时的内存中完成，保存的作者源文件未修改。

这说明公开实现即使给单位图，也未保证本站与其他节点完全隔离。若用于我们的无邻站消融，必须先修正并做邻站扰动测试。此结论针对核查时的公开代码，不代替对论文正式结果的完整复核。

## 8. 作者关系清单能否帮助我们补水文连接

额外做了保守的同名筛查：作者清单60个站，在本地750站中有16个江西省站；以省份＋去空白后的断面名匹配，得到13个唯一同名候选，2条作者直接边可两端映射：

- 孔目江江口（本地S0727）→罗坊（S0726）。
- 罗坊（S0726）→肖江江口（S0756）。

对应文件为`作者站点与本地同名核对.csv`和`作者关系可同名映射候选.csv`。同名仍需核对原站点编号、断面沿革和位置；目前没有将这两条边添加到任何模型，也没有将其称为已验证真值。若核实成功，可作为更有依据的局部水文连接先验，并沿作者关系链检查未直接相邻的上下游可达关系。
